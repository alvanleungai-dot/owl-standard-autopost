## Q1 — do weekly generators reach Playwright `schedule-week.mjs`?

No. All four reach generation plus Telegram review only:

- Sunmood executes `./gen-week.mjs` ([scripts/sunmood/weekly-run.mjs:4-13](scripts/sunmood/weekly-run.mjs#L4)); its child dispatches configured poster generators ([scripts/sunmood/gen-week.mjs:54-56](scripts/sunmood/gen-week.mjs#L54)).
- Bright Day executes `./gen-week.mjs` ([scripts/bright-day/weekly-run.mjs:10-19](scripts/bright-day/weekly-run.mjs#L10)); its child dispatches poster generators ([scripts/bright-day/gen-week.mjs:83-85](scripts/bright-day/gen-week.mjs#L83)).
- TML executes only `./gen-week.mjs` ([scripts/tml/weekly-run.mjs:17-21](scripts/tml/weekly-run.mjs#L17)); the `schedule-week` string is only the Telegram instruction ([scripts/tml/weekly-run.mjs:33](scripts/tml/weekly-run.mjs#L33)).
- Better Life executes only `../gen-week.mjs` ([scripts/better-life/weekly-run.mjs:17-21](scripts/better-life/weekly-run.mjs#L17)); its `schedule-week` string is also only notification text ([scripts/better-life/weekly-run.mjs:33](scripts/better-life/weekly-run.mjs#L33)).

Therefore the four generators are not browser-dependent through their current executable graph. They still cannot be moved *as-is* because their creation/ledger/review state is written in the deploy checkout.

## Q2 — can Watchdog and a publisher double-post the same slot?

**Yes.** A concrete automatic FB+IG double-post path exists if a previously scheduled TML Graph post is delayed or not visible in the Page timeline when Watchdog runs:

1. `SCE-FB-Topup` reaches TML's API scheduler ([scripts/fb-topup.mjs:11-14](scripts/fb-topup.mjs#L11)). That scheduler creates a scheduled FB photo post and records `fbPostId` in the manifest only after the POST returns ([scripts/tml/api-schedule.mjs:70-83](scripts/tml/api-schedule.mjs#L70)).
2. On the following HK day, Watchdog does not consult `fbPostId`: it starts from *all approved* posts ([scripts/watchdog.mjs:88-93](scripts/watchdog.mjs#L88)), compares only caption markers found on the visible Page timeline ([scripts/watchdog.mjs:117-120](scripts/watchdog.mjs#L117)), and treats past-dated missing markers as overdue ([scripts/lib/watchdog-core.mjs:25-30](scripts/lib/watchdog-core.mjs#L25)). A scheduled post that Meta has not yet made visible therefore remains eligible.
3. Watchdog launches `tml/schedule-week.mjs --only=<index>` ([scripts/watchdog.mjs:124-130](scripts/watchdog.mjs#L124)). That child also pre-scans the visible Page only ([scripts/tml/schedule-week.mjs:94-103](scripts/tml/schedule-week.mjs#L94)), then sees the past slot and clicks **Publish** now ([scripts/tml/schedule-week.mjs:136-138](scripts/tml/schedule-week.mjs#L136), [187-188](scripts/tml/schedule-week.mjs#L187)). If Meta later delivers the original scheduled Graph post, the client FB Page has two posts; the browser composer is documented as FB+IG ([scripts/tml/schedule-week.mjs:1-2](scripts/tml/schedule-week.mjs#L1)), so IG can also duplicate.

There is also a direct same-slot double-publish race for TML Instagram, and an operator-triggered FB+IG race:

1. On an overdue TML post missing from the FB scan, Watchdog launches `tml/schedule-week.mjs --only=<index>` ([scripts/watchdog.mjs:117-130](scripts/watchdog.mjs#L117)). That browser composer publishes/schedules both channels ([scripts/tml/schedule-week.mjs:1-2](scripts/tml/schedule-week.mjs#L1), [187-188](scripts/tml/schedule-week.mjs#L187)).
2. At the same time, `TML-IG-Daily` treats every approved post with `date <= today` and no `igPostId` as due ([scripts/tml/api-ig-daily.mjs:65-73](scripts/tml/api-ig-daily.mjs#L65)) and calls `/media_publish` ([scripts/tml/api-ig-daily.mjs:48-52](scripts/tml/api-ig-daily.mjs#L48)). The browser scheduler does not write `igPostId` (its only local output is screenshots: [scripts/tml/schedule-week.mjs:182-207](scripts/tml/schedule-week.mjs#L182)).
3. There is no shared lock or atomic claim in either path; both check remote/local state before committing. Thus both can publish the same TML creative to IG. The browser path also creates the FB post, but the scheduled IG path does not create FB, so this particular scheduled-job race is not a double FB Page post.

Separately, a human/manual concurrent `tml/schedule-week.mjs` invocation can race Watchdog to a double **FB+IG** browser commit: both pre-scan the page ([scripts/tml/schedule-week.mjs:94-103](scripts/tml/schedule-week.mjs#L94)) and no lock prevents both from reaching the commit click ([scripts/tml/schedule-week.mjs:187-208](scripts/tml/schedule-week.mjs#L187)).

`SCE-Watchdog` is the scheduled job with that operational dependency: it directly launches persistent Chrome against `secrets/better-life/chrome-profile` and `secrets/tml/chrome-profile` ([scripts/watchdog.mjs:29-39](scripts/watchdog.mjs#L29), [56-58](scripts/watchdog.mjs#L56)). None of the other 13 named entrypoints imports Playwright or names a Chrome profile on its executable path.

## Ranked cutover risk

1. **`SCE-Gatekeeper` + `SCE-FB-Topup` (highest FB Page double-post risk).** Gatekeeper can auto-run `fb-topup` for a backlog ([scripts/lib/gatekeeper-core.mjs:190-221](scripts/lib/gatekeeper-core.mjs#L190), [scripts/gatekeeper.mjs:336-344](scripts/gatekeeper.mjs#L336)), while `SCE-FB-Topup` independently runs the same four schedulers ([scripts/fb-topup.mjs:11-14](scripts/fb-topup.mjs#L11)). The schedulers check `fbPostId` and live-page state, then POST and only afterwards write `fbPostId` ([scripts/sunmood/api-schedule.mjs:63-85](scripts/sunmood/api-schedule.mjs#L63)); no cross-process lock prevents both workers from reading “unscheduled” and each scheduling a live client FB post.
2. **`SCE-Watchdog` (highest Chrome/session and TML IG duplicate risk).** It must stay local and its late browser auto-fix races the independently scheduled TML IG daily publisher as traced in Q2.
3. **`TML-IG-Daily` / `BetterLife-IG-Daily`.** Both use check-then-publish-then-write-ID sequencing ([scripts/tml/api-ig-daily.mjs:65-76](scripts/tml/api-ig-daily.mjs#L65); [scripts/better-life/api-ig-daily.mjs:56-67](scripts/better-life/api-ig-daily.mjs#L56)); a Render retry/overlap can duplicate an IG post.
4. **Four weekly runners + `SCE-Catchup`.** They do not post live, but lost checkout state can regenerate/re-reserve content and re-open later publishing/dedup risk. Catchup decides from absence of a local week file ([scripts/catchup.mjs:46-47](scripts/catchup.mjs#L46)).
